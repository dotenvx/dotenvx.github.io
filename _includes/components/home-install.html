Explain that dotenvx injects values into the child process without requiring application-specific dotenv code. 4. Encrypt `.env` using local `.env.keys` file storage when prompted: dotenvx encrypt Show that `HELLO` is now stored as an `encrypted:` value without printing unnecessary ciphertext. Explain the key model: - `.env` contains ciphertext and `DOTENV_PUBLIC_KEY`, so it can be safely committed and shared. - `.env.keys` contains `DOTENV_PRIVATE_KEY`, which grants decryption authority and must never be committed or exposed. - The public key can encrypt values; the private key can decrypt them. Confirm `.env.keys` exists without displaying its private-key value. 5. Prove the encrypted environment remains usable: dotenvx get HELLO dotenvx run -- node index.js Confirm they recover `World` and `Hello World` through decryption. 6. Update the encrypted value without decrypting the file: dotenvx set HELLO "Sword" dotenvx get HELLO dotenvx run -- node index.js Confirm they return `Sword` and `Hello Sword`. Explain that `dotenvx set` uses the public key to update encrypted values safely. 7. Demonstrate safe output handling: dotenvx run --redact -- node -e "console.log(process.env.HELLO)" Explain how `--redact` helps prevent injected secrets from leaking into terminal and agent output. 8. Create and wield multiple encrypted environments: echo "HELLO=Development" > .env.development echo "HELLO=Production" > .env.production dotenvx encrypt -f .env.development dotenvx encrypt -f .env.production Use local `.env.keys` file storage when prompted. Confirm both files contain encrypted values without displaying private keys. Then run: dotenvx get HELLO -f .env.development dotenvx get HELLO -f .env.production dotenvx run -f .env.development -- node index.js dotenvx run -f .env.production -- node index.js Confirm the environments return `Development` and `Production`, and the app prints `Hello Development` and `Hello Production`. Explain that each encrypted `.env.*` file is independently versioned, while `-f` selects which environment dotenvx reads, updates, validates, or injects. 9. Update production without decrypting its file: dotenvx set HELLO "Production v2" -f .env.production dotenvx get HELLO -f .env.production dotenvx run -f .env.production -- node index.js Confirm the production environment remains encrypted while returning the updated value. 10.
